## Techs
    - Player AI feedback system:
        - All code related to player detection by Macro AI has been refactorised and moved to a dedicated module.

    - Audio Design 
        - First update on the native engine:
            - All Sound Cue have been redo to use MetaSounds Sources.
            - Old sound class override in sound mix was replaced by Audio modulation and Sound Control Bus mix for the volume settings.
            - All AudioVolume actors were replaced by the new AudioGameplayVolume.
            - MMVS now use the Submix system to manage sound effects.

        - Second update on the Wwise integration:
            - Audio Engine Update: Unreal Engine 5.4.4 -> Wwise 2022.1.19 -> Wwise 2024.1.8
            - The full audio system have been reworked to use Wwise features:
                - Some features are still used like the Sound Control Bus but this time it's used to control Wwise.
            - New effect system.

    - Debug menus:
        - New debug menu for musics
        - New debug menu for Audio
        - New AI contextual feedback debug menu. 
            (Like in the main debug menu but only for the AI feedback.)
        - Calibrator moved in a new menu specific for the calibrator.
    
    - Interaction system:
        - More modular interaction script with interaction state and script modifiers.
            (can and easily plug modifiers in an interaction without creating a custom class for each interaction.)
        - Interaction script for comunication between scripts was moved in C++.
        - Interaction now support action type (Press, Release, etc.)

    - Game Master:
        - Full refactorisation of the game master root code.
        - Root code moved from blueprint to C++.
        - Support for multiple game masters in a same game in the root code.
            (Full support planned in the future)
        - New game master observers, selections and tools to make dev use friendly user.
        - New Fx management.

    - Tracking Point System:
        - Base script was moved from blueprint to C++ and now support custom movement modifiers. 
            (Like the interaction system, useful when a game master or AI use custom movement to follow a target or animate the movement to a specific point.)
        - Optimizated method calculation to check is in zone and better zone shape management.
        - Support Preview System to manage effects and preview tracking movement without impacting the true tracking point transform.

    - Perception Tracking Proxy:
        - Moved from blueprint to C++ and now support new movement methods with velocity follow.

    - Digestive System:
        The Digestive system was not split in three different modules:
        - TagDynamicMeshMorph to manage the physical, collision, and rendering mesh morphing.
        - TagDigestiveSystem to manage the digestive system logic and interactions.
        - TalasDigestiveSystem to manage Talas digestive system specific logic and assets.
        Big refactoring about the section management and tick management.
        New dynamic audio listeners for world sounds when you are in the digestive system.
